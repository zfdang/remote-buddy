Why do some remotes only support Hold-to-Talk and not Hands-Free Toggle?

The root cause lies in the hardware circuitry and Bluetooth audio firmware design:

Hardware-gated Microphone Power (e.g. Xiaomi): Most remotes manufactured for consumer streaming boxes strictly tie microphone power to the physical button depression. The microphone circuit is only powered on while the button is actively held down by your finger. The moment you release it, the onboard microcontroller immediately cuts microphone power and terminates the BLE audio stream. Because its firmware does not support host-initiated remote mic keep-awake commands, software on the Mac cannot force the remote to continue transmitting audio after release.

Why changing input tool settings doesn't help: Some users try setting their input method (e.g. Apple Dictation or WeChat Keyboard) to "Tap to Start / Tap to Stop". While this changes the app's software expectation, it cannot change the physical power cut-off in the remote. Once released, the remote ceases transmitting audio packets, leaving the input tool with silence.

Which remotes support true Hands-Free Toggle?
Google G9N9N: Implements advanced bidirectional commands. When tapped, Remote Buddy sends BLE control directives to keep the remote's microphone powered (indicated by the solid white LED) until tapped again.
T1 Air Mouse Remote: The factory firmware natively follows a "press once to start streaming, press again to stop" toggle behavior without requiring continuous finger pressure.

Why do some remotes (like Xiaomi) have a 60-second hardware voice limit?

Firmware Mechanism: TV remotes manufactured for consumer set-top boxes are designed strictly for searching movies or issuing brief commands. To prevent battery drain when a button is accidentally compressed in couch cushions, the internal microcontroller firmware includes a hard-coded watchdog timer: audio streaming is forcibly terminated after approximately 60 seconds. Once this timeout triggers, the hardware stops transmitting packets regardless of host requests until the button is released and pressed again.

Why do certain models and batches exceed the 60s limit?

Some remotes supporting bidirectional ATVV commands honor host keepalive requests. Remote Buddy sends periodic ATVV MIC_EXTEND keepalive packets every 10 seconds during a session and applies a configurable host auto-stop cap in General settings (5 minutes by default; selectable as 3 / 5 / 10 / 15 / 30 minutes to avoid draining the battery if left running).

However, not every remote model or compatible batch supports exceeding 60s—actual behavior depends on firmware honoring MIC_EXTEND:

  • G9N9N 0x0110 / FW 26.2: Verified on real hardware to stream continuously past 60s (68.9s hands-free via MIC_EXTEND).
  • T1 Air-Mouse Remote (tested sample): Verified continuously for nearly 2 minutes; third-party clone batches require individual verification.
  • G9N9N 0x011B (zhuhai_jieli compatible batch, per #280 ↗): Community testing showed firmware ignores MIC_EXTEND and stops silently around 60.6s without AUDIO_STOP, so sessions remain capped at ~60s in the current version; 26.7 and 26.0 await long-duration validation.

INTERACTION MODES

2. Voice Triggers & Button Modes

What is the difference between Hold-to-Talk and Hands-Free Toggle?

Remote Buddy offers two foundational voice trigger paradigms, plus a hybrid Smart Toggle mode on G9N9N:

1. Hold to Talk (Walkie-Talkie style):
Press and hold the voice button while speaking; release it immediately when done. Audio streaming stops and text is inserted into the active text field. Best for quick chat replies, prompt queries, and fleeting thoughts.

2. Hands-Free Toggle (Tap to Start / Tap to Stop):
Press the button once to begin recording. You can set the remote down, reference notes, or type freely while speaking. Press the button a second time to conclude recording and commit the recognized text. Ideal for long-form dictation and conference remarks.

3. Smart Toggle (G9N9N Default · Recommended):
Intelligently arbitrates based on press duration: releases within 0.7 seconds are treated as Hands-Free Toggle (audio continues until the next tap); holding past 0.7 seconds automatically activates Hold-to-Talk (audio ends immediately upon release). You get both paradigms on a single physical key without configuration switches.

Why is using the Fn / Globe (🌐) key as a voice shortcut discouraged, and what is recommended instead?

Core Reason: The Fn / Globe (🌐) key is the single most conflict-prone hotkey across macOS and desktop applications.

  • Frequent Third-Party App Hijacking: Popular applications—most notably the WeChat macOS desktop client—frequently register global listeners for the Fn key. When hijacked, pressing the remote voice button sends Fn directly to WeChat instead of your intended voice dictation tool.
  • macOS System Interception: By default, macOS binds the 🌐 key to "Show Emoji & Symbols" or "Change Input Source", causing unexpected popups or input layout switching.
  • High Troubleshooting Burden: Single-key collisions can be subtle and frustrating to diagnose, forcing users to comb through multiple system panes and third-party app settings.

Strongly Recommended Best Practice:

Configure both Remote Buddy and your voice input tool to use a custom multi-modifier shortcut (such as Ctrl (⌃) + Option (⌥) + V):

Multi-modifier combinations provide exceptional global uniqueness and are virtually never claimed by system defaults or everyday software, ensuring reliable, maintenance-free triggering out of the box.

What actions can I assign in Button Mapping, and what are some practical examples?

On the Button Mapping tab, you can independently customize Single Press, Double Press, and Long Press gestures for every physical key (except the dedicated Voice button). Each remote saves its own configuration independently.

Available action categories:

  • Basic Keys: Frequent editing and navigation shortcuts such as Return, Send (⌘↩), Shift+Return, Copy/Paste, Undo, cursor arrows, and scrolling.
  • System & Media: App Switcher (⌘Tab), Mission Control, Spotlight, Play/Pause, Next/Previous Track, system volume and display brightness controls, or disabling unused keys.
  • Open an App: Pick built-in preset apps (Chrome, WeChat, Cursor, ChatGPT, Claude, Terminal, etc.) or select Open Custom App to pick any app installed on your Mac—with optional auto-focus via an app shortcut or saved Accessibility input field.
  • Common Phrases: Open the floating phrase panel to paste frequent snippets, prompts, or commands in one click.
  • Custom Actions:
    • Custom Shortcut: Record any custom keystroke or multi-modifier keyboard shortcut used by your editor or workflow.
    • Open URL / URL Scheme: Enter any web link (https://...) or app URL scheme such as Apple Shortcuts (shortcuts://run-shortcut?name=MyShortcut) to launch websites or trigger multi-step workflows safely.
  • Direct Passthrough (directional keys): Acts like a physical arrow key with zero gesture delay, ideal for holding Right Arrow to fast-forward video playback or continuous cursor movement.

Common setup examples:

  1. Launch a favorite app with one button: Map the YouTube or NETFLIX key's single press to Open an App (or Open Custom App for Cursor or WeChat) so one tap brings it forward ready for voice input.
  2. Open a web app or run an Apple Shortcut combo: Assign a spare key or double press to Open URL / URL Scheme—use https://chatgpt.com to jump straight to a site, or shortcuts://run-shortcut?name=WorkMode to execute a multi-step Apple Shortcut workflow.
  3. Layer custom shortcuts onto Long Press: Keep single press intuitive (like OK = Return, Long Press = Send), and map another key's long press to a Custom Shortcut such as ⇧⌘P or ⌘Space to double your shortcuts without cluttering single taps.
Can I set different button mappings for specific apps?

Yes. Remote Buddy supports per-app button overrides, stored independently for each remote without affecting other remotes.

How to configure:

  1. Open Button Mapping and look at the Application bar above the remote layout, which defaults to All Applications (Default) (the remote's baseline mapping used across all apps).
  2. Click + Add Application on the right to pick from Running Applications, or choose Choose Application… to select any app on your Mac.
  3. With that app selected, customize only the buttons or gestures you want to behave differently there (Single Press, Double Press, Long Press, including custom shortcuts, basic keys, or Direct Passthrough for directional keys). Unmodified triggers automatically inherit the remote's default mapping.
  4. To clear a single override, open that trigger's editor and click Restore Default; to remove all overrides for that app, click Remove Application on the Application bar.

Automatic switching: Whenever a configured app is your frontmost window, Remote Buddy automatically applies its overrides; as soon as you switch to another app, buttons immediately fall back to your remote's defaults (or the newly focused app's overrides).

Common examples:

  • Browsers & video players (Chrome, Safari, IINA): Override Right Arrow to Direct Passthrough for hold-to-2x playback speed and OK to Play/Pause, while keeping normal arrows and Return/Send everywhere else.
  • Code editors & terminals (Cursor, VS Code, Antigravity): Map a convenient button to the command palette (⇧⌘P) or submit shortcut only while coding.
  • Presentation apps (Keynote / PowerPoint): Dedicate arrow buttons to slide navigation without altering your global defaults.
What is "Direct Passthrough" and when should I use it?

Background: Regular buttons in Remote Buddy support Single Tap, Double Tap, and Long Press gestures. To differentiate a single tap from a double tap, the software must wait a brief arbitration window before emitting keystrokes; furthermore, default long-press behaviors enter rapid-fire repeating single clicks every 100ms after a 350ms hold delay (software rapid-fire).

How Direct Passthrough Works: Direct Passthrough bypasses all gesture delays, tap arbitrations, and repeat loops. When a direction key (Up, Down, Left, Right) is pressed, Remote Buddy dispatches an authentic KeyDown event to macOS with zero latency. When your finger releases the button, an authentic KeyUp event is dispatched immediately. It behaves exactly like a real physical keyboard arrow key.

Primary Use Cases:

  1. Holding Right Arrow for 2x Video Speed: In Bilibili, YouTube, and desktop media players, holding down the keyboard right arrow (→) speeds up playback (e.g. 2x or 3x speed), returning to normal speed upon release. In Direct Passthrough mode, holding right direction key performs genuine speed-up seamlessly—eliminating key repeat jumps!
  2. Smooth Document Navigation & Gaming: Fine cursor adjustments, continuous smooth page scrolling, and retro emulator direction controls.
  3. Built-in Safety Watchdog: Direct Passthrough includes a 60-second safety watchdog. Even in the event of extreme Bluetooth packet loss, it automatically releases stuck keys after timeout, preventing infinite keystroke repetition.
What are "Common Phrases" and how do I set them up?

Purpose: Allows one-touch insertion of frequently used static text—such as email addresses, shipping coordinates, customer support templates, terminal commands, or code snippets—without typing or speaking them repeatedly.

How to Configure:

  1. Open the Button Mapping tab in Remote Buddy, click any button trigger (Single, Double, or Long Press), switch to the Common Phrases action category, and click Edit Common Phrases to open the phrase manager.
  2. In the phrase manager, edit phrase text, assign concise labels, and map phrases directly to remote physical keys (directional arrows, OK, and available function keys).
  3. In Button Mapping, assign any remote button gesture to the "Common Phrases" action.

Usage & Exclusive Handling: When the phrases shortcut is pressed, a floating panel appears displaying bound phrases for each key. Remote buttons are exclusively captured by the panel—pressing any assigned button immediately inserts the phrase via simulated Command+V into the active text field. Once dismissed, all buttons instantly resume their standard mapping or passthrough actions.

What do "Hold" vs "Tap" mean in Input Tool Settings, and how do they differ from remote gestures?

It is easy to conflate remote hardware gestures with input tool trigger modes. In reality, they are two completely decoupled layers, and Remote Buddy acts as an intelligent bidirectional translation bridge between them:

The Core Difference:
1. Remote Hardware Gestures (Hold vs Tap): Describes how your fingers physically interact with the handheld remote (whether you prefer walkie-talkie style Hold-to-Talk, or hands-free Tap-to-Start / Tap-to-Stop).
2. Input Tool Trigger Modes (Hold vs Tap): Refers strictly to the hotkey protocol expected by the dictation app itself.

How Remote Buddy Performs Bidirectional Conversions (With Concrete Examples):

  • Example 1: Remote is in Hands-Free Tap mode, but the input tool only supports Hold mode:
    Conversion mechanism: When you tap the remote voice button once, Remote Buddy sends a synthetic hotkey KeyDown (hold down without releasing) to macOS. The input tool perceives a held shortcut and starts recording while your hands are completely free. When you finish speaking and tap the remote again, Remote Buddy sends a synthetic KeyUp (release). The input tool receives the release event, terminates recording, and inserts the transcribed text.
  • Example 2: Remote only supports Hold mode (e.g. Xiaomi), but the input tool only supports Tap mode (e.g. Apple Dictation):
    Conversion mechanism: When you press and hold the remote voice button, Remote Buddy sends a complete keystroke pulse (KeyDown + KeyUp) to start the input tool. When you release your finger from the remote, Remote Buddy detects the physical release and automatically sends a second complete keystroke pulse (KeyDown + KeyUp) to stop the input tool and finalize transcription.

Our Recommended Best Practice: Always set your input tool to "Hold Mode" (Hold to Talk)!

In input tools that let you choose how hotkeys behave (such as Doubao, WeChat Keyboard, or Voice Buddy), we strongly recommend configuring the input tool to "Hold Mode":

  1. Rock-Solid State Certainty (Never Invert or De-sync): Tap mode relies on toggles—the exact same shortcut starts recording on one press and stops on the next. If the input tool ever lags or loses focus, a missed keystroke causes state inversion (starting when you intended to stop). In contrast, Hold mode uses deterministic levels: KeyDown unequivocally means "record now", and KeyUp unequivocally means "stop and commit". It is mathematically immune to toggle de-sync.
  2. Total Remote Freedom: With the input tool in Hold mode, you can use whatever remote gesture you prefer—Hold-to-Talk, Hands-Free Toggle, or G9N9N's Smart Toggle. Remote Buddy faithfully maintains the synthetic KeyDown/KeyUp state under the hood for maximum reliability.

Takeaway Tip: Set your input tool software to "Hold Mode" (Hold to Talk), leave Remote Buddy's default setting as "Tap mode: Off" (do not enable the Tap mode toggle in the wizard), and then hold or tap your physical remote however you please—Remote Buddy handles the translation seamlessly!

What does the "\"Global Shortcut\" Enabled" toggle under WeChat or Doubao Input Method do?

Background & Default Behavior: Both WeChat Input Method and Doubao Input Method register as macOS Input Sources. By default, if you are currently using the default ABC (English) layout or another input method, Remote Buddy proactively calls the macOS Text Input Services (TIS) API to switch the active input source to WeChat/Doubao upon pressing the voice button to ensure dictation can be triggered.

Why Was This Option Introduced?
In focus-sensitive applications—such as Antigravity, VS Code, terminal emulators, or code editors—system-level input source switching can occasionally cause the active text cursor to lose focus or introduce a brief UI stutter.
Fortunately, both modern input methods have their own native background daemon capable of intercepting hotkeys system-wide:

  • WeChat Input Method: Supports "Global shortcut" (快捷键全局生效) in its preferences.
  • Doubao Input Method: Supports "Global voice activation" (全局唤起语音) in its preferences.

What This Toggle Does:

  1. Bypasses Input Source Switching to Prevent Focus Loss: When enabled in Remote Buddy's "Input Tools" settings, Buddy completely skips proactive macOS input source switching and dispatches the voice hotkey directly. This permanently eliminates cursor focus loss in Antigravity, VS Code, and similar editors.
  2. Zero-Latency Instant Trigger: Removing the macOS input source switch reduces latency, making speech recognition start immediately without hitching.

Important Prerequisite:
Before enabling this option in Remote Buddy, make sure the corresponding global feature is enabled in your input tool's own preferences:
• WeChat Input Method: Open WeChat Keyboard Preferences → Shortcuts → check "Global shortcut".
• Doubao Input Method: Open Doubao Preferences → Voice Input → enable "Global voice activation".
Note: If the input method's internal global daemon is turned off, enabling this bypass toggle in Remote Buddy may prevent voice invocation when typing in an English (ABC) layout.

SECURITY & HELP

5. Permissions, Security & Troubleshooting

macOS says the .pkg installer “cannot be opened because the developer cannot be verified” or “Apple could not verify it is free of malware”. What should I do?

This is standard macOS Gatekeeper behavior for open-source installers that are not Apple-notarized. Remote Buddy is free, open-source software under GPL-3.0-only and currently does not use a paid Apple Developer ID certificate for Apple notarization. As a result, macOS attaches a quarantine attribute to .pkg files downloaded via a browser (including both the app installer and the universal uninstaller). As long as you downloaded the package from our official mirror (remote.zfdang.com) or zfdang/remote-buddy Releases ↗, it is safe to install using any of the following methods:

  1. Method 1: Control-click → Open in Finder (Recommended for most macOS versions)
    Open Finder → Downloads, hold Control and click (or right-click) the .pkg file, select Open, and click Open again in the confirmation dialog to start the installer. (Note: On macOS 15 Sequoia and newer, if the dialog no longer offers an “Open” button, use Method 2 below.)
  2. Method 2: Allow in System Settings (Works on macOS 14, 15, and newer)
    Dismiss the Gatekeeper warning dialog, open System Settings → Privacy & Security, scroll down to the Security section, find the message stating that Remote_Buddy_...pkg was blocked, click Open Anyway, and authenticate with your password or Touch ID.
  3. Method 3: Remove the quarantine attribute in Terminal
    Run the following command in Terminal to clear the quarantine flag, then double-click the .pkg file to install normally (adjust the filename if installing the uninstaller or another filename):
    xattr -d com.apple.quarantine ~/Downloads/Remote_Buddy_*.pkg

You only need to approve the installer once during installation; normal app launches and virtual microphone operation will not repeatedly trigger this prompt.

Why does the app require Accessibility, Input Monitoring, and Microphone Driver permissions?

Privacy Commitment: Remote Buddy operates 100% locally with zero telemetry, zero analytics, and zero audio archiving. Both the app and its driver are fully open-source under GPL-3.0-only on GitHub.

Each system permission serves a dedicated purpose:

  • CoreAudio Driver (Remote Buddy Mic): A system-level virtual audio driver. When the remote sends raw compressed Bluetooth audio, Remote Buddy decodes it into 16kHz PCM audio and feeds it to this driver, presenting your remote as a standard studio microphone to macOS.
  • Accessibility: Required to synthesize keypresses, render the floating phrases wheel, and inspect window accessibility trees for input focus.
  • Input Monitoring: Allows the app to capture hardware HID events from backgrounded remotes reliably.
Voice works, but buttons do not? Check device access in Karabiner-Elements and other key remappers.

A remapper can take exclusive access to the remote, preventing Buddy from receiving its buttons. Ordinary buttons may stop performing their assigned actions while Bluetooth or voice input still works. For Xiaomi remotes, the defaults are: Home switches apps, TV plays or pauses media, Power sends Backspace, and Back sends Escape.

  1. Open Devices in Karabiner-Elements and find your remote, such as the Xiaomi Bluetooth Voice Remote.
  2. Turn off Modify events for that remote so Buddy can handle it. Keep your other keyboard settings.
  3. Reconnect the remote or restart Buddy, check its status in Button Mapping, and test the home, TV, power, and back buttons.

If Buddy still reports that another input tool owns the device, restart Karabiner-Elements and try again. Also check Buddy’s Input Monitoring and Accessibility permissions.

Chose Fn as your voice shortcut, but WeChat hijacks it? Clear WeChat’s global Fn shortcut.

The WeChat macOS desktop app can register Fn as a global shortcut (such as global voice input or another hotkey). While WeChat holds that global shortcut, pressing your remote’s voice button sends Fn to WeChat instead of your chosen input tool (Doubao, WeType, Tencent Chatterfly, Typeless, etc.).

  1. Open the WeChat desktop app → Settings → Shortcuts.
  2. Check whether any global shortcut—especially a voice shortcut—is bound to Fn (or the 🌐 Globe key).
  3. If it conflicts, reassign or clear only the conflicting Fn shortcut (you can leave all other WeChat shortcuts as-is).
  4. Return to your input tool or Buddy’s Voice Test step and press the remote voice button again.

If you prefer to keep WeChat’s Fn binding, switch Buddy’s voice shortcut in Input Tools → Voice Shortcut to another combination such as Ctrl (⌃) + Option (⌥) + V.

Chose Fn as your voice shortcut, but macOS hasn’t set Fn to “Do Nothing”?

When using Fn/Globe with a third-party voice tool, pressing the remote button may pop up the Emoji & Symbols picker, switch keyboard layouts, or trigger system Dictation instead if macOS intercepts the Globe key at the system level.

  1. Open System Settings → Keyboard on your Mac.
  2. Locate Press 🌐 key to and change it to Do Nothing.
  3. Once set to Do Nothing, macOS passes Fn events cleanly to your third-party voice tool.

Note: If you selected macOS Dictation as your input tool, keep the system 🌐 key active and set Dictation → Shortcut to Press 🌐 key twice as shown in the Setup Wizard.

Why don’t system shortcut actions like Mission Control, Notification Center, Show Desktop, or Spotlight trigger?

How It Works: System & Media presets in Remote Buddy—such as Mission Control (⌃↑), Notification Center (fn N), Show Desktop (fn F11), Previous/Next Space (⌃← / ⌃→), Spotlight (⌘Space), Screenshot (⇧⌘5)—as well as chords added via Custom Shortcut, simply synthesize standard macOS keyboard shortcuts rather than calling private system APIs.

Because of this, whether an action triggers depends directly on your macOS Keyboard Shortcuts configuration:

  1. Check the actual shortcut toggles in macOS:
    Open System Settings → Keyboard → Keyboard Shortcuts… → Mission Control (and related categories such as Spotlight or Screenshots). Verify that the corresponding shortcut is checked/enabled and still matches the key combination (for example, Mission Control → ⌃↑, Application windows → ⌃↓, Show Desktop → F11).
  2. Do not confuse behavior settings with shortcut settings:
    In modern macOS, System Settings → Desktop & Dock → Mission Control only controls window grouping and Spaces behavior—it does not enable or configure keyboard shortcuts. Shortcut bindings are managed exclusively under Keyboard → Keyboard Shortcuts….
  3. Multi-input-source conflict on Spotlight (⌘Space):
    On Macs with multiple input sources enabled, ⌘Space may be assigned to “Select the previous input source” instead of Spotlight. Verify or adjust the assignment under Keyboard Shortcuts → Spotlight / Input Sources.
  4. Using custom macOS shortcuts instead of defaults?
    If you prefer non-default system shortcuts, select Custom Shortcut in Remote Buddy’s Button Mapping editor and pick your exact system key combination using the built-in virtual keyboard.

Why do shortcuts or phrases fail to paste inside password fields or secure terminals?

This is standard macOS kernel-level protection, not a bug.

macOS enforces Secure Input Mode whenever focus is positioned within password fields, Keychain prompts, credential vaults (such as 1Password or Bitwarden), or hardened terminal sessions. In this mode, macOS kernel blocks third-party background applications from monitoring keystrokes or automating synthetic keyboard inputs to protect passwords against keyloggers.

As soon as you tab away or switch to normal text fields, all shortcuts and phrase paste operations resume immediately.

How do I reset pairing or change remote batteries?

To reconnect across different computers or clear bluetooth connection glitches:

  1. Google G9N9N:
    • Pairing Broadcast: Press and hold both the Back and Home buttons for ~3 seconds until the bottom white indicator LED pulses slowly. Forget the remote in macOS Bluetooth settings and re-pair.
    • Factory Hard Reset: If Bluetooth becomes unresponsive, remove both AAA batteries, press and hold the Home button while reinserting the batteries, and keep holding until the LED pulses. The remote resets completely and enters pairing mode. (Note: The G9N9N remote itself has no physical pairing buttons; do not confuse it with the button on the Chromecast streaming dongle).
  2. Xiaomi Remote 2 / 2 Pro (RC001 / RC003):
    • Pairing Broadcast: Hold the remote close to your Mac (10–20 cm) and press and hold both "Home" and "Menu" buttons for 3–5 seconds until the LED flashes rapidly (or a beep sounds). Pair via macOS Bluetooth settings.
    • Reset / Clear Binding: Forget the device in the previous host's Bluetooth settings. On RC001, remove the AAA batteries to power-cycle; on 2 Pro, connect a USB-C cable to wake and reset.
  3. T1 Air Mouse Remote (T1-Remote):
    • Direct Bluetooth Pairing: Press and hold both Home and Back buttons until the LED transitions from rapid flashing to a slow pulse. Connect directly to T1-Remote in macOS Bluetooth settings (do not use the 2.4 GHz USB receiver).
    • Power Cycle: Remove the battery for a few seconds (or plug in USB-C on rechargeable variants) and re-pair using Home + Back.

WINDOWS EDITION

6. Windows Installation & Usage Guide

How do I install and get started on Windows after downloading?

The Windows edition is published as a self-contained .NET 10 LTS portable archive—no separate .NET runtime installation is required. Follow these steps to set everything up:

  1. Download and extract completely: Download Remote_Buddy_Windows_*_x64.zip from the Windows section of the Downloads page and extract it to a permanent folder (for example, D:\Tools\RemoteBuddy). Do not launch the app directly from inside a zip preview window.
  2. Launch as Administrator: Open the extracted folder, right-click RemoteBuddy.App.exe, choose Run as administrator, and accept the UAC prompt. If Windows SmartScreen appears on first launch, click More info → Run anyway.
  3. Install VB-CABLE and reboot Windows: On Step 2 of the setup wizard (Virtual Audio Driver Check), if VB-CABLE is not detected, click Install VB-CABLE (安装 VB-CABLE). Remote Buddy downloads VBCABLE_Driver_Pack46.zip from our website mirror (falling back to VB-Audio if needed), verifies its SHA-256 hash, and launches the official installer—click Install Driver, then reboot Windows so the audio service registers the virtual endpoints.
  4. Pair via Bluetooth and click Connect inside the app: Pair your remote in Windows Bluetooth settings (or scan in Step 3 of the wizard). Important: Even after Windows shows the remote as Paired or Connected, click Connect inside Remote Buddy's wizard or Devices page to open the ATVV voice link.
  5. Select the virtual microphone and pass the voice test: In your voice input tool, set the microphone to CABLE Output (VB-Audio Virtual Cable), match the voice shortcut configured in Remote Buddy, and complete the wizard's voice transcription verification step.
Why is VB-CABLE required on Windows, and what if my speakers go silent after installing it?

Why is a third-party driver needed?
On 64-bit Windows 10/11, Driver Signature Enforcement (DSE) requires every kernel audio driver (.sys) to carry Microsoft WHQL certification—self-signed drivers are rejected by the OS. Rather than forcing users into Windows Test Mode, the Windows edition uses the WHQL-certified VB-CABLE virtual audio cable by VB-Audio Software (Donationware): Remote Buddy writes decoded 16 kHz PCM speech into CABLE Input, and your dictation tool listens on CABLE Output.

Two ways to install:

  • In-app one-click installer (Recommended): Click Install VB-CABLE in Step 2 of the wizard or on the Permissions & Driver (权限与驱动) page, confirm elevation, click Install Driver, and reboot Windows.
  • Manual download: Download VBCABLE_Driver_Pack46.zip from the Downloads page or from vb-audio.com/Cable ↗, unzip it, run VBCABLE_Setup_x64.exe as Administrator, click Install Driver, and reboot Windows.

Common VB-CABLE troubleshooting:

  • My speakers or headphones have no sound after installing VB-CABLE: Windows sometimes automatically switches the default playback output device to CABLE Input (VB-Audio Virtual Cable). Click the taskbar speaker icon (or open Settings → System → Sound) and switch your default Output back to your physical speakers or headphones, while keeping CABLE Output (VB-Audio Virtual Cable) selected as the microphone in your voice input tool.
  • Reboot required / device not ready: VB-CABLE requires a Windows restart after driver installation to initialize the audio endpoints properly.
  • Device disabled: Open Windows Sound Settings → More sound settings and verify both CABLE Input (Playback) and CABLE Output (Recording) are enabled.
Why is running Remote Buddy as Administrator strongly recommended on Windows?

While the app can launch under a standard user account, running Remote Buddy as Administrator unlocks full functionality and avoids UAC friction for four specific technical reasons:

  1. Complete remote button capture (BthPort ETW): On Windows, most ordinary buttons on Google Chromecast (G9N9N)—as well as Back, Volume+, and Volume− on Xiaomi Remote 2 Pro (RC003)—are not exposed completely through standard Raw Input and must be decoded via Windows kernel Bluetooth tracing (BthPort ETW). Running elevated lets ETW run natively inside the main process without spawning separate UAC helper prompts.
  2. Doubao Input Method USB/IP virtual keyboard: Doubao's Hold-to-Talk ignores synthetic SendInput events flagged with LLKHF_INJECTED. When Doubao is selected, Remote Buddy uses the Microsoft-signed usbip-win2 host controller and HIDMaestro virtual keyboard so key events appear as hardware input—this driver path requires Administrator privileges.
  3. Windows UIPI (User Interface Privilege Isolation): Non-elevated apps are blocked by Windows from sending shortcuts or pasting phrases into elevated windows (such as an Admin PowerShell/CMD terminal, Task Manager, or elevated tools). Running Remote Buddy elevated lets it type into elevated apps too.
  4. Driver installation & Bluetooth adapter recovery: Installing VB-CABLE or using the wizard's Restart Bluetooth Adapter recovery button requires Administrator rights.

Tip — Always launch elevated automatically:
Right-click RemoteBuddy.App.exe → Properties → Compatibility → check "Run this program as an administrator". If you are already running normally, open Permissions & Driver (权限与驱动) inside the app and click Restart as Administrator (以管理员身份重启本程序).

How should I configure WeChat Input, Doubao, Windows Dictation, and Typeless on Windows?

Universal rule: Set the recording microphone in your chosen tool (or Windows Sound input for system dictation) to CABLE Output (VB-Audio Virtual Cable) and match its trigger shortcut with Remote Buddy.

  • WeChat Input Method (WeType): In WeChat Input Settings → Voice Input, enable Global shortcut (快捷键全局生效) and set it to Hold to talk (按住说话, default shortcut Ctrl + F5). Choose CABLE Output (VB-Audio Virtual Cable) as the microphone and keep Remote Buddy in Hold-to-Talk mode.
  • Doubao Input Method / Desktop Client: In Doubao Settings → Voice Input, set Global voice activation (全局唤起语音) to Continuous mode (持续模式), choose CABLE Output (VB-Audio Virtual Cable) as the microphone, and match the Hold-mode shortcut including exact left/right modifier keys (e.g., default Right Alt RAlt, or Left Ctrl + Shift + D). Run Remote Buddy as Administrator and choose Hold-to-Talk; first use prepares the signed USB/IP virtual keyboard driver.
  • Windows Dictation (Win + H): Built into Windows 10/11—no third-party software needed. Set your Windows default input microphone to CABLE Output (VB-Audio Virtual Cable) and choose Windows Dictation (Win + H, toggle start/stop).
  • Typeless & Other Voice Apps: Typeless defaults to Ctrl + Alt + V (Hold-to-Talk). Any tool supporting a global hotkey and microphone selection works by choosing CABLE Output and entering the same hotkey in Remote Buddy's wizard.
Windows Troubleshooting & Key Differences (Additive Mapping, Paired but No Response, SmartScreen)
  • Why do native remote actions (like system volume or Home) sometimes still happen alongside custom mappings?
    Windows Raw Input is a passive sink and cannot selectively block a specific remote's native keys without using a global low-level hook that lacks per-device handles (which would block your physical keyboard keys too). Therefore, ordinary keys on Windows use Additive Mapping: your custom shortcut or snippet fires while native OS actions (such as volume adjustments) may also take effect.
  • My remote shows Paired/Connected in Windows Bluetooth settings, but voice or buttons don't respond:
    1) Make sure you clicked Connect inside Remote Buddy's setup wizard or Devices page to establish the ATVV voice connection;
    2) If voice works on G9N9N (or Xiaomi RC003 Back / Vol+ / Vol− don't respond), open Permissions & Driver (权限与驱动) and check that Remote Buddy is running as Administrator and the ETW button capture service is active;
    3) If the Bluetooth stack gets stuck or key events appear truncated, click Restart Bluetooth Adapter in the wizard (or disable and re-enable your Bluetooth adapter in Windows Device Manager) and reconnect.
  • Why does Windows SmartScreen show an unrecognized app warning on first launch?
    Because Remote Buddy is a free GPL-3.0-only open-source project without a paid commercial Authenticode signing certificate, Windows Defender SmartScreen may display an "unrecognized app" prompt. As long as you downloaded from remote.zfdang.com or zfdang/remote-buddy-windows ↗, click More info → Run anyway.
