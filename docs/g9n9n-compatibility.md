# G9N9N 语音与按键使用指南

更新日期：2026-11-22。市面上的 G9N9N 遥控器即使 VID/PID 同为 `18D1:9450`、DIS 型号同报 `A0`，**甚至连 `HID 版本` 同为 `0x0110`**，在不同硬件修订或固件版本下，macOS 公开 `IOHID` 层收到的普通按键行为也存在**多种不同表现**。Remote Buddy 会读取并在「遥控器连接」页展示 **HID 版本**（来自蓝牙 `PnP ID 0x2A50` 与公开 `IOHID kIOHIDVersionNumberKey`）以及固件版本、硬件修订，并提供对应的支持模式：

| 已知 HID / 固件批次 | 普通按键报告格式与长度 | macOS 系统层识别表现 | Remote Buddy 支持模式与功能边界 |
| --- | --- | --- | --- |
| **HID 版本 `0x0110` / 固件 `26.2`**（`PVT/MP`，已实测完全支持） | Report ID `1`，描述符 3 字节、固件实际发完整 3 字节索引格式（如松开 `01 00 00`） | 单键按下与松开均正常通过 `BTLEServer` 上送公开 `IOHID` | **Fully Supported（完全支持模式）**：<br>语音键（含智能切换与约 5 分钟保活）+ 全部 14 颗普通按键的单击、双击、长按与单键常用语 |
| **DIS `A0` / 固件 `26.7`（已抓包）<br>与 `HID 0x0110` / 固件 `26.0`（`CR PVT/MP`，见 [#256](https://github.com/zfdang/remote-buddy/issues/256)）** | • `固件 26.7`：Report ID `1`，描述符 2 槽位（含 ID 3 字节），但单键按下/松开固件仅发送 **1 字节**（`03` / `00`）；<br>• `0x0110 / 固件 26.0`：最大输入报告 3 字节，原始 BLE 报文待抓包确认（可能是类似短报告，或新的硬件/固件变体） | 单键按下与松开未进入公开 `IOHID`（`26.7` 已抓包确认为 1 字节短报告被丢弃，`26.0` 待抓包定性）；**同时按两个键**可上送 3 字节（如 `01 03 0B` / `01 07 04`）进入 `IOHID` | **Partially Supported（部分支持 / 双键兼容模式）**：<br>1. 语音键（含智能切换与约 5 分钟保活）可正常使用；<br>2. 仅「方向键 + OK」（如「上 + OK」）可发送 Enter 键；14 颗普通单键、双击/长按及单键常用语不可用 |
| **HID 版本 `0x011B`**（社区实测反馈，详见 [brightac/remote-buddy#7](https://github.com/brightac/remote-buddy/issues/7)） | Report ID `2`（小端 16-bit consumer usage），描述符声明不含 ID 3 字节、固件实际仅发 **2 字节**（如按下 `42 00`、松开 `00 00`） | 因实际长度与描述符不符，**所有普通按键报告均在 macOS `BTLEServer` 层被丢弃，公开 `IOHID` 连双键都收不到任何普通按键** | **仅语音键可用（普通按键不受公开接口支持）**：<br>ATVV 语音键走独立通道仍可正常录音；因本项目严格遵循只调用公开系统 API 原则，不会读取系统底层调试日志来绕过拦截，建议更换为已验证支持单键的完全支持批次（如 `0x0110 / 固件 26.2`）或其他支持型号 |

> **关键说明与更换建议**：
> - 连上 Mac 后，可在 Remote Buddy **设置 → 遥控器连接 → 硬件信息网格** 查看 **`HID 版本`**（例如 `0x0110` 或 `0x011B`）以及**固件版本**与**硬件修订**，方便在遇到按键无响应时迅速鉴别批次。
> - **仅凭 `HID 版本 0x0110` 并不能保证单键完全可用**：目前已经观测到同为 `0x0110` 的不同固件/硬件变体中，既有完全支持 14 颗单键的 `固件 26.2（PVT/MP）`，也有仅双键可进 `IOHID` 的 `固件 26.0（CR PVT/MP）`（见 [#256](https://github.com/zfdang/remote-buddy/issues/256)）。因此请以向导中的实际单键测试结果为准。
> - 如果您的 G9N9N 属于部分支持情况（单按不被 macOS 识别，只能靠双键组合触发），**必须由用户在向导中主动勾选确认进入 Partially Supported（部分支持）模式**；程序不会绕过您的确认自动切入有限支持模式。如果属于 `0x011B` 这类连双键都无法到达 `IOHID` 的批次，向导中语音仍可测试通过，但普通按键均无法通过公开接口接收，建议更换为已验证支持单键的批次（如 `0x0110 / 固件 26.2`）或其他遥控器。

G9N9N 兼容款众多，同为 VID/PID `18D1:9450`、DIS 型号 `A0` 甚至同为 `HID 版本 0x0110` 的设备，仍可能属于上述不同固件或硬件表现。购买与版本识别请查看[设备页面](https://remote.zfdang.com/device.html)；型号名称、相同 VID/PID 或单一 HID 版本号都不能代替实际单键按键测试。

本次验证的完全支持样机（`0x0110 / 固件 26.2`）由项目维护者实际购买并验证，[购买链接（拼多多，实购约 ¥15）](https://mobile.yangkeduo.com/goods.html?ps=wI005ehWCi)（不同批次卖家的固件与硬件修订可能随时变更，仍请以上手向导实测为准）。

## 首次设置与模式识别

1. 在 macOS 蓝牙设置中连接遥控器；配对时同时按住返回和主页约 3 秒。
2. 在向导选择 G9N9N，先**单按 OK 键**测试：
   - **若收到单键输入**：自动判定为**完全支持模式**，随后依次单按三个不同的普通按键即可进入语音配置。
   - **若单按无反应**：向导提示尝试同时按住 **「上 + OK」**（任意方向键 + OK）。若只有双键组合才触发识别，需由用户**主动勾选启用「部分支持（双键兼容）模式」**，随后确认一次「方向键 + OK」可用即可继续语音配置，完成页会明确提示当前仅支持语音键和「方向键 + OK」发 Enter。

## 按键映射与兼容模式

在“按键映射”选择 G9N9N 并开启开关：

- **完全支持模式**：方向、OK、返回、主页、静音、音量加减、YouTube、Netflix、输入源和电源共 14 颗普通按键，可配置单击、双击和长按。YouTube 默认上一首，Netflix 默认下一首，输入源默认播放／暂停；均支持自定义。单项“恢复默认”和整机重置使用同一套型号默认动作；设备首次从未知型号识别为 G9N9N 时，会补齐缺失的型号默认动作（已有自定义包括主动设为未设置会保留）。
- **部分支持模式（双键兼容）**：该模式已在首次/添加设备向导中锁定，设置页仅作只读展示（不可在设置页切换或修改任何键位），仅响应 **「方向键 + OK」→ 发送一次 Enter（回车）**，并隐藏不适用的 14 颗单键及单键常用语编辑项。如后续更换为完全支持款硬件，请在“连接”页面移除旧设备后通过“添加新设备”向导重新识别。

语音键始终固定用于遥控器麦克风，电量服务有读数时设备卡片显示电量百分比。

## 语音操作

默认支持**智能切换（点按免提）**：短按 Google Assistant 语音键并松手后保持免提收音（再按语音键或按其他键停止），长按超过 0.7 秒则松手即停；也可在「遥控器连接」设置中切换为纯「按住说话」。两种模式均突破 60 秒时长上限（自动保活最长约 5 分钟），音频由遥控器麦克风送入 Remote Buddy Mic 再交给所选输入工具识别，且两种按键支持模式下的语音体验完全一致。

[完整支持与部分支持（A0 / 26.7 及 #256 反馈 26.0）真机记录](g9n9n-hardware-debugging.md)。

## 硬件与报告边界

部分支持模式下不通过双键组合推断全部 14 颗单键，也不开放缺乏松开报告的按键连发或长按逻辑，仅稳定提供「方向键 + OK」模拟 Enter 键。已识别的短零值松开报告会清除按键状态，不会作为新的电源键输入。
