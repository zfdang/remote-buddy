G9N9N Voice & Button Compatibility Guide

Even when G9N9N remotes share the same VID/PID (18D1:9450), model (A0), and HID version (0x0110), ordinary button behavior on macOS varies by hardware revision and firmware. Remote Buddy now supports all known G9N9N batches with full 14-button mapping and ATVV voice via two paths: plug-and-play Standard System HID, or opt-in Bluetooth Logging Profile (.mobileconfig) recovery for batches whose short reports are dropped by macOS BTLEServer. Check Settings → Connection → Hardware info for your unit's HID version, firmware, and Button Integration path.

Two Integration Paths: Remote Buddy supports all known G9N9N batches—the only difference is the transport path: Standard System HID works out of the box, whereas Bluetooth Logging Profile (.mobileconfig) recovers dropped reports when enabled and installed. Open Settings → Connection → Hardware info to check your unit's Button Integration path, HID version, and firmware revision; for profile-free plug-and-play support, choose a verified native unit on the Supported Remotes & Buying Guide → (maintainer-tested 0x0110 / FW 26.2 reference: Pinduoduo (~¥15) ↗).

First-Time Setup & Integration Paths

Marketing names or shared VID/PID (18D1:9450) alone cannot verify button behavior; onboarding detects your unit's path and enables full 14-button support accordingly.

1. Onboarding Detection

Bluetooth pairing & Step 2 check
Guided flow
  • Bluetooth pairing: Connect the remote in macOS Bluetooth settings; hold Back + Home for ~3 seconds to enter pairing mode.
  • Press OK alone first: When public IOHID delivers a single-key press, Remote Buddy marks the unit as Standard System HID (native Full Support) and proceeds to test three buttons.
  • Enable Log Recovery if single keys fail: Turn on opt-in Bluetooth log key recovery in onboarding, install the bundled .mobileconfig profile in System Settings → Device Management, click Recheck, and press OK to complete full 14-button setup.

2. Different Paths, Identical Full Capabilities

Standard System HID vs. .mobileconfig Profile
Full 14-button support
  • All 14 ordinary buttons: Both integration paths support single, double, and long-press actions, hold repeat, and common phrases for all 14 buttons.
  • Clear integration indicator: Settings → Connection → Hardware Info clearly displays whether each device uses Standard System HID or Bluetooth Logging Profile (.mobileconfig).
  • Native isolation: Units verified for native IOHID remain isolated from log recovery so keys never double-fire.

Voice Input & HID Report Boundaries

Voice capture, Smart Toggle, and keepalive work identically across both integration paths; optional Bluetooth log recovery stays off by default and strictly scoped to com.apple.bluetooth for paired G9N9N remotes.

Voice key & Smart Toggle

Dedicated ATVV audio channel
Works on all batches
  • Dedicated microphone trigger: The Google Assistant button always controls Remote Buddy Mic and your selected dictation or voice tool; the bottom white LED stays lit while streaming audio, and battery percentage appears when readable.
  • Smart Toggle (default): Tap and release to speak hands-free (press again or press another key to stop), or hold past 0.7s to stop on release. Pure Push-to-Talk is also selectable in Connection settings.
  • Exceeds the 60s limit: Background keepalive supports continuous sessions up to ~5 minutes before auto-stopping to protect battery life.

Safety boundaries & references

Public IOHID API compliance
Scope limits
  • Native isolation: Units verified for native IOHID continue using IOHID only and never double-fire even if the log recovery toggle is enabled.
  • Opt-in Bluetooth logging profile (off by default, confirmed-only, fail-closed): For pending-verification batches (0x011B, 26.7) dropped by macOS BTLEServer, Remote Buddy never reads system logs by default; only when you explicitly turn on the toggle, the device has a verified HID fingerprint binding, and profile inspection confirms the bundled com.apple.bluetooth .mobileconfig profile is installed does it start the subsystem == "com.apple.bluetooth" log stream in memory—keeping reading stopped whenever status is unknown/uninstalled or <private> redaction is observed until you click Recheck.
