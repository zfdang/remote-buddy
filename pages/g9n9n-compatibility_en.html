G9N9N Voice & Button Compatibility Guide

Even when third-party or OEM G9N9N remotes share the same VID/PID (18D1:9450) and report DIS model A0, they exhibit three distinct HID / firmware behaviors on macOS. Remote Buddy reads and displays the HID version (from Bluetooth PnP ID 0x2A50 and public IOHID kIOHIDVersionNumberKey) in Connection settings so you can verify your batch and supported mode.

Observed HID / firmware batch Status Ordinary button report payload macOS IOHID behavior Remote Buddy support mode & limits
HID version 0x0110
Tested & verified		 Fully Supported Report ID 1 with 3-byte descriptor; firmware sends complete 3-byte indexed payloads (for example, 01 00 00 on release). Single-key press and release reports pass cleanly through BTLEServer to public IOHID. Fully Supported: Voice key (including Smart Toggle and ~5 min keepalive) + custom single, double, long presses, and common phrases on all 14 ordinary buttons.
DIS A0 / FW 26.7
Tested partial batch		 Partially Supported Report ID 1 declares two key slots (3 bytes total with ID), but firmware sends only 1 byte (03 / 00) for single-key presses and releases. 1-byte short reports are dropped by macOS; only simultaneous 2-key chords filling both slots (e.g. 01 03 0B) reach public IOHID. Partially Supported (2-key compatibility mode): Voice works normally; ordinary input is limited to Direction + OK (such as Up + OK) sending Return/Enter. Single-key remapping, multi-tap, and single-key phrases are unavailable.
HID version 0x011B
Community tested		 Voice Only Report ID 2 (16-bit consumer usage) declares 3 bytes excluding ID, but firmware sends only 2 bytes (e.g. 42 00 press, 00 00 release). Because payload size mismatches the HID descriptor, all ordinary button reports are dropped by macOS BTLEServer—neither single keys nor 2-key chords reach public IOHID. Voice only (ordinary buttons unsupported via public APIs): ATVV voice recording still works over its separate channel. Remote Buddy strictly uses public macOS APIs; we recommend replacing 0x011B hardware with a verified 0x0110 batch or another supported model.
Identification & replacement guidance: After pairing with your Mac, open Remote Buddy Settings → Connection → Hardware info to check your remote's HID version (such as 0x0110 or 0x011B) and firmware revision. If single buttons do not register and only 2-key chords work, you must explicitly opt in during onboarding to enter Partially Supported mode—the app never silently downgrades without confirmation. If your unit is a 0x011B batch where even 2-key chords cannot reach IOHID, see the Supported Remotes & Buying Guide → (maintainer-tested 0x0110 unit reference: Pinduoduo product page (~¥15) ↗).

First-Time Setup & Button Mapping Modes

Marketing names or shared VID/PID (18D1:9450) alone cannot verify button compatibility; onboarding locks the appropriate mode based on live key tests.

1. Onboarding detection

Bluetooth pairing & Step 2 check
Guided flow
  • Bluetooth pairing: Connect the remote in macOS Bluetooth settings; hold Back + Home for ~3 seconds to enter pairing mode.
  • Press OK alone first: When onboarding detects a single-key OK press, it automatically enables Fully Supported mode and asks you to test three distinct ordinary buttons before voice setup.
  • If single presses produce no event: Onboarding prompts you to hold Up + OK (any D-pad direction + OK). If only 2-key chords register, tick Confirm partial support (compatibility mode) and verify one chord to continue.

2. Mapping capabilities by mode

Fully Supported vs. Partial Support
Locked per mode
  • Fully Supported (14 buttons): Remap single, double, and long presses for D-pad directions, OK, Back, Home, Mute, Volume +/-, YouTube, Netflix, Input, and Power. Defaults: YouTube = Previous track, Netflix = Next track, Input = Play/Pause.
  • Partially Supported (read-only lock): Once opted in during setup, Connection settings show the mode as read-only, map Direction + OK → Return/Enter, and hide inapplicable 14-button and single-key phrase editors.
  • Switching to a 0x0110 unit later: Remove the old profile in Connection settings and run Add New Device to test single-key support cleanly.

Voice Input & HID Report Boundaries

Voice capture works identically across modes; ordinary key customization is enabled only when macOS delivers unambiguous public HID events.

Voice key & Smart Toggle

Dedicated ATVV audio channel
Works on all batches
  • Dedicated microphone trigger: The Google Assistant button always controls Remote Buddy Mic and your selected dictation or voice tool; the bottom white LED stays lit while streaming audio, and battery percentage appears when readable.
  • Smart Toggle (default): Tap and release to speak hands-free (press again or press another key to stop), or hold past 0.7s to stop on release. Pure Push-to-Talk is also selectable in Connection settings.
  • Exceeds the 60s limit: Background keepalive supports continuous sessions up to ~5 minutes before auto-stopping to protect battery life.

Safety boundaries & references

Public IOHID API compliance
Scope limits
  • No speculative chord decoding: Partially Supported mode never guesses individual keys or synthesized long-press repeats from 2-key chords without release reports; recognized zeroed short release reports clear key state safely without firing Power.
  • No private log scraping: For 0x011B units dropped inside macOS BTLEServer, Remote Buddy never reads private system logs to bypass OS boundaries.
