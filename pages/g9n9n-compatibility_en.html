G9N9N Voice & Button Compatibility Guide

Even when third-party or OEM G9N9N remotes share the same VID/PID (18D1:9450), DIS model (A0), and even the same HID version (0x0110), ordinary button behavior in macOS public IOHID can still vary across hardware revisions and firmware builds. Remote Buddy reads and displays the HID version (from Bluetooth PnP ID 0x2A50 and public IOHID kIOHIDVersionNumberKey), firmware revision, and hardware revision in Connection settings so you can verify your unit and supported mode.

First-Time Setup & Integration Paths

Marketing names or shared VID/PID (18D1:9450) alone cannot verify button behavior; onboarding records whether your unit works via native IOHID or the Bluetooth logging profile.

1. Onboarding Detection

Bluetooth pairing & Step 2 check
Guided flow
  • Bluetooth pairing: Connect the remote in macOS Bluetooth settings; hold Back + Home for ~3 seconds to enter pairing mode.
  • Press OK alone first: When public IOHID delivers a single-key press, Remote Buddy marks the unit as Standard System HID (native Full Support) and proceeds to test three buttons.
  • Enable Log Recovery if single keys fail: Turn on opt-in Bluetooth log key recovery in onboarding, install the bundled .mobileconfig profile, then press OK to verify all 14 buttons via the logging profile path.

2. Full 14-Button Mapping on Both Paths

Standard System HID vs. .mobileconfig Profile
Full 14-button support
  • All 14 ordinary buttons: Both integration paths support single, double, and long-press actions plus common phrases for all 14 buttons.
  • Clear integration indicator: Connection details and Button Mapping display whether each device uses Standard System HID or Bluetooth Logging Profile (.mobileconfig).
  • Native isolation: Units verified for native IOHID remain isolated from log recovery so keys never double-fire.

Voice Input & HID Report Boundaries

Voice capture works identically across modes; ordinary key customization is enabled only when macOS delivers unambiguous public HID events.

Voice key & Smart Toggle

Dedicated ATVV audio channel
Works on all batches
  • Dedicated microphone trigger: The Google Assistant button always controls Remote Buddy Mic and your selected dictation or voice tool; the bottom white LED stays lit while streaming audio, and battery percentage appears when readable.
  • Smart Toggle (default): Tap and release to speak hands-free (press again or press another key to stop), or hold past 0.7s to stop on release. Pure Push-to-Talk is also selectable in Connection settings.
  • Exceeds the 60s limit: Background keepalive supports continuous sessions up to ~5 minutes before auto-stopping to protect battery life.

Safety boundaries & references

Public IOHID API compliance
Scope limits
  • Native isolation: Units verified for native IOHID continue using IOHID only and never double-fire even if the log recovery toggle is enabled.
  • Opt-in Bluetooth logging profile (off by default, confirmed-only, fail-closed): For pending-verification batches (0x011B, 26.7) dropped by macOS BTLEServer, Remote Buddy never reads system logs by default; only when you explicitly turn on the toggle, the device has a verified HID fingerprint binding, and profile inspection confirms the bundled com.apple.bluetooth .mobileconfig profile is installed does it start the subsystem == "com.apple.bluetooth" log stream in memory—keeping reading stopped whenever status is unknown/uninstalled or <private> redaction is observed until you click Recheck.
  • Further reading: Compare all remote hardware on the Supported Remotes page →, or inspect byte-level capture logs on GitHub in G9N9N hardware debugging notes ↗, community report #256 (0x0110 / FW 26.0) ↗, and community report #7 (0x011B) ↗.
