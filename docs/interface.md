# macOS 界面与使用流程

主导航默认打开通用页，分为三组并以分割线隔开：通用、权限与麦克风、遥控器连接、输入法集成；按键映射、应用集成；关于。

1. **通用**：顶部三张状态卡依次显示权限与麦克风、已连接遥控器名称、输入法集成。点击卡片进入对应设置页；卡片下方可重新运行设置向导。其余偏好分为应用显示、启动行为和语言。
2. **权限与麦克风**：蓝牙、输入监控、辅助功能三项授权，以及虚拟麦克风驱动状态。全部授权且检测到驱动后概览卡才显示就绪。通用和权限页显示期间每秒刷新权限；设备列表通过 Core Audio 通知更新，进入页面时也会刷新。
3. **遥控器连接**：右上角“添加新设备”；每台遥控器单独分组显示名称、图片、连接状态和增益，增益独立保存。
4. **输入法集成**：顶部先显示已保存的热键和点按模式，随后仅显示当前集成工具名称；微信输入法、豆包输入法、腾讯Chatterfly、[Voice Buddy（语音搭子）](https://myvoicebuddy.com/)、网易叭哥说、Typeless、macOS 听写与其他工具的配置向导入口。概览显示所选工具名称，不代表已通过语音输入验证。
5. **按键映射**：顶部选择已记录设备，配置普通硬件按键动作、快捷键和常用语；语音设置入口跳转到输入法集成。
6. **应用集成**：位于“关于”前，列出微信、Antigravity、ChatGPT、Claude 和 WorkBuddy；默认全部关闭，可逐项切换，也可全部开启或全部关闭。每项说明对应的输入位置。只有按下语音键时，才检查当前前台应用；已有可编辑输入焦点时保留当前输入框，否则尝试定位当前窗口的对话输入框；完成聚焦尝试后才继续准备并发送语音触发键，普通应用切换不会触发。需要辅助功能权限，聚焦是可选环节，找不到明确目标或无法确认聚焦时会显示提示并继续语音输入；若输入工具将识别结果留在剪贴板，可用 Command+V 手动粘贴。应用切换、语音结束、系统睡眠或关闭集成会取消待执行的聚焦，不会追随到其他窗口或在松开后补发语音触发键。准备过程有等待上限，期间的音频只在内存中限量暂存，取消即丢弃。开启任意应用集成时，Fn 按住模式也接管原生 Fn 以保证聚焦先于触发；Fn 点按模式在既有音频暂存流程中等待聚焦。Antigravity 针对 Agent 聊天输入框，微信需先打开会话。
7. **关于**：保留应用图标和简介；版本信息、软件更新、诊断与日志、项目链接分别分组。常用语从按键映射页进入。

侧栏使用较紧凑的上下间距，保留每项图标与文字；小窗口仍可滚动。

应用集成只读取输入控件的类型、标识、标签和位置等元数据，不读取消息正文、聊天记录或私有配置，也不自动输入或发送消息。目标控件不明确、被遮挡或目标应用不公开可用控件时，自动聚焦可能失败；应用会提示结果并继续语音输入，必要时可用 Command+V 粘贴。Antigravity 集成针对 Agent 桌面应用，不包含单独的 Antigravity IDE。

输入法集成通过设置向导配置并验证，不读取其他应用的私有配置，也不把检测到安装当作兼容验证。Voice Buddy 有独立入口与介绍卡片，引导配置所选语音热键、录音模式与 `Remote Buddy Mic` 并检查安装状态。重新选择输入工具不会清除遥控器档案、增益或普通按键映射。

使用微信输入法或豆包等支持「全局唤起」的输入工具时，语音触发前不会主动调用系统 API 切换输入法，而是先等待输入工具通过自身的全局快捷键完成切换；若在激活等待超时内未检测到切换，才会回退调用 `TISSelectInputSource` 兜底——这样无论用户是否开启全局唤起都能正常工作，且避免了主动切换与 Electron 等应用文本输入客户端绑定发生竞争。成功触发后不自动切回，避免打断异步识别和文本提交。需要换回其他输入法时，可手动切换。Voice Buddy 等独立工具不切换系统输入法，沿用各自的语音快捷键和文本回填流程。

开启自定义按键映射、软件语音按键或 Fn 点按模式后，若同时使用多只遥控器、设备重连或服务较晚就绪，应用会在设备发现回调、语音结束或下一次语音开始前自动校验并补齐系统键值映射，不会因短暂断开而重置已开启的 Fn 点按偏好；若蓝牙遥控器接入时系统语音键仍在生效，可按一次语音或手动刷新连接完成补齐。

## 常见问题的入口

- 系统设置开关已开、App 却认为未授权：在权限页核对状态。临时开发签名变化会使旧授权失效，需要添加当前 App 并重新授权。
- 安装驱动后没有麦克风：在权限页刷新设备，确认 Remote Buddy Mic 已检测到；必要时重新安装当前架构的最新 PKG，并按提示重启 Mac，使 Core Audio 重新加载驱动。
- 遥控器连不上或不识别按键：进入遥控器连接检查具体设备与连接状态；检查权限页输入监控授权。
- Mac 睡眠后反复亮屏或唤醒：参见下方[睡眠唤醒排查](#睡眠唤醒排查)。
- TV 键、返回键等失效但语音正常：检查 Karabiner-Elements 的 Devices，关闭这只遥控器的 Modify events，保留其他键盘设置，重连遥控器或重启遥控搭子。若仍提示设备占用，可重启 Karabiner；检查输入监控和辅助功能授权。详见[官网排障](https://remote.zfdang.com/#troubleshooting)与[官方设备设置](https://karabiner-elements.pqrs.org/docs/manual/configuration/configure-devices/)。
- 有声音却无法输入：进入输入法集成，核对目标工具的麦克风、语音快捷键和按下／松开行为，再运行实际输入测试。
- 需要从头检查配置：通用页状态卡下方重新运行向导。该流程不清除现有硬件连接与普通按键配置。

菜单栏使用提供的单色图片，提供 1x／2x 资源；准备输入框及等待输入工具就绪期间显示沙漏，提示“正在准备语音输入”；传输语音时才使用带圆点的图片，设备断开时图标灰显。白色背景已转换为透明，模板图像由系统适配浅色和深色菜单栏。图标由 `scripts/generate-icons.py` 去除白底并缩放生成。

首次设置向导先检查权限，顶部逐项显示八个步骤：权限与麦克风、选择遥控器型号、连接遥控器、按键测试、语音热键、输入工具、语音测试和完成。第一步同时检查三项权限及 Remote Buddy Mic，不依赖预先选择设备。权限缺失在对应行处理；麦克风明确区分未检测到、准备中、准备失败和已就绪，失败时提供重试与安装说明，不重复显示普通排障卡。麦克风只显示一张状态卡，右侧也仅显示一项；内部仍检查设备检测、路由选择和音频输出就绪；第 5 步选择语音热键。首次使用默认跟随系统语言，第一步左下角可选择系统默认、中文或英文，选择持久保存。

第 2 步用单选圆点表示当前设备选择，五项设备均可选择。小米、T1 和 Google G9N9N 可进入连接页；GY3LE 与 Siri Remote 点击继续后留在此页，显示尚未支持的提示。G9N9N 已验证版本支持普通按键映射；向导使用单键检测，且保留连接及语音验证。

Google 遥控器配对：打开 Mac 的“系统设置 → 蓝牙”，同时按住遥控器返回（Back）和主页（Home）直到指示灯闪烁，再在蓝牙列表中选择并连接。连接后按普通按键检查输入；重新配对时可先忽略原设备，不需要等待电视上的配对提示。

输入法候选框正在显示时，方向键和 Return 通常用于选词。请先选词确认或按 Escape 取消预编辑，再启动语音输入；程序不会自动发送 Escape，以免丢弃尚未确认的文字或关闭目标应用的对话框。

“添加新设备”只走设备选择、连接、按键测试和完成；输入工具的配置向导依次进入语音热键、输入工具、语音测试和完成，不重复首次设置中的权限与麦克风步骤。两种入口都保留已有设备与按键配置。连接与按键测试页正常等待时不显示警告卡；“按键没反应？”默认折叠，展开后提供检查步骤、重新检测和用于反馈问题的诊断复制入口。

常用语管理从按键映射进入，可将短语绑定到按键。普通原生文本框优先使用公开 AX 接口；检测到终端、Web 内容、Electron 编辑器，或文本控件不支持 AX 写入时，使用临时剪贴板与 Cmd+V。剪贴板原有各项格式仅暂存在内存，粘贴后尝试恢复；期间检测到用户复制新内容时保留新内容。安全输入、敏感控件、非终端的无法确认目标及已有文本选区会拒绝插入。只发送粘贴指令不代表目标应用已经提交文本，具体终端和编辑器仍需兼容性验收。为保障安全性与路径可预测性，cmux 终端焦点集成仅查找 App Bundle 内部及标准路径（`/opt/homebrew/bin/cmux`、`/usr/local/bin/cmux`），安装在自定义 PATH 的二进制不会被执行（系统仅记录日志并沿用普通前置）。


## 固定输出与设备增益

所有遥控器共用 Remote Buddy Mic（UID `BuddyMic2ch_UID`）。正常页面及向导不提供输出设备选择，
不会切到扬声器或 BlackHole；更改 macOS 默认扬声器、麦克风也不会改变此路由。
第 1 步检查驱动与固定输出，第 3 步连接设备，第 4 步测试按键，第 5 步设置语音热键。程序自动配置虚拟麦克风，
驱动已检测且输出就绪后启用“继续”，由用户点击后进入下一步；前进和返回时均停留在本页。失败时提供重试、安装说明和重启 Mac 的提示。
设备增益随各自档案保存，向导语音测试的增益只修改当前遥控器；切换遥控器不改变其他设备的增益。

## 按键长按与持续连发

方向键、电源键和音量键在持续按住 350ms 后进入自动连发（删除动作每 50ms 重复一次，其他动作每 100ms 重复一次）；其他按键默认禁用长按（可在按键映射中配置），配置了长按动作的按键在持续按住 550ms 后触发对应的长按动作。为防止蓝牙丢包或异常断开导致按键卡死，系统具备持续报告续期与看门狗机制：按住期间只要收到设备报告即维持按下状态；非连发按键在 8 秒无报告后保护性释放；连发和原生方向键透传不受该静默超时影响。删除连发按住 15 秒、其他按键按住 60 秒后触发保护性释放，并暂时抑制后续卡死报告；物理松开会清除抑制，无后续报告时抑制也会在 8 秒后过期。

小米蓝牙遥控器的新安装缺省映射：Home 单击为 Command+Tab（切换任务），TV 单击为媒体播放／暂停，OK 长按为 Command+Enter。已有安装保留已保存的映射，包括尚未设置的 OK 长按动作；主动恢复默认映射时使用这些新缺省值。

每个普通按键分别配置单击、双击和长按动作。点击动作编辑面板后，顶部提供分类标签（基础按键、媒体与音量、系统与应用、常用语、自定义快捷键），方便快速筛选候选动作；选定动作即时保存生效。如需还原单个触发条件的配置，可点击“恢复此项默认”；如需重置整只遥控器，可在页面底部点击“恢复全部默认”。

长按设置随设备的按键映射保存。未配置双击的单按操作天然支持连续快速点按，无需额外开关。按键映射页底部亦提供“编辑常用语”快速入口，方便直接前往常用语配置面板。

## 睡眠唤醒排查

遥控搭子在 Mac 进入系统睡眠（`.systemWillSleep`）或会话切至后台（`.sessionDidResignActive`）时会自动停止 HID 监听（包括输入监控、事件过滤与权限轮询）、取消常用语待插入队列、停用虚拟音频输出并挂起非就绪蓝牙连接的扫描／退避，再在系统恢复时按状态重建。

但蓝牙遥控器作为 HID 输入设备由 macOS 系统蓝牙服务（`bluetoothd`）管理，退出遥控搭子并不会断开系统级的蓝牙 HID 配对或移除硬件唤醒能力，也不一定能阻止遥控器或系统内部事件唤醒 Mac。[相关设备的实测调查](https://github.com/HD838A/remote-mic-app/issues/486#issuecomment-6635487347)发现，即使应用自身的蓝牙连接已断开，系统仍可能因蓝牙 HID 活动从暗唤醒进入完全唤醒。这是另一组设备和系统的结果，不能直接确定当前 Mac 的唤醒原因，本项目也尚未在实体硬件上完成针对睡眠唤醒抑制的实机验收。

1. 睡前关闭遥控器或取出电池，再在相同条件下测试睡眠；恢复供电后重复测试。若只有供电时复现，遥控器可能参与了唤醒。也可在系统设置的蓝牙列表中断开设备后测试，但系统可能自动重连。
2. 在终端运行 `pmset -g log` 查看睡眠、暗唤醒（DarkWake）和完全唤醒历史，或运行 `pmset -g assertions` 查看当前阻止睡眠的电源断言。对照复现时间查看相关记录；HID 或蓝牙字样本身不足以确认是哪台设备。前者是历史记录，后者只反映查看时的状态。
3. 若问题仍在，反馈 Mac 型号、macOS 版本、遥控器型号，以及供电与断电两次测试的结果和相关时间段日志。分享前请检查并删去设备名称、标识符等不愿公开的信息。

如系统提供允许蓝牙设备唤醒电脑的设置，也可自行尝试关闭；这可能同时影响蓝牙键盘和鼠标唤醒，本项目未验证其在各版本 macOS 上的可用性或效果。

## 语音触发热键

输入法集成页只显示正式的语音热键和点按模式。修改必须进入输入法集成向导，先选择待测试配置，再配置工具并完成真实语音转文字测试。测试期间仅临时使用候选配置，正式设置与磁盘中的正式配置保持不变；通过后才一并提交，取消或测试失败不覆盖原配置。预置菜单提供 Fn、右 Option、右 Command，以及 Control + Shift、Control + Option、Control + Command 分别与 V 或 R 组成的 6 组快捷键共 9 项；左 Command／Option 及其他修饰键加普通按键的组合可通过自定义弹窗选择。语音热键以文字、括号内符号和加号显示，如 `Ctrl (⌃) + Option (⌥) + V`。自定义弹窗按 MacBook ANSI 布局摆放，左右修饰键可分别选择。界面草稿和实体键录入均保留左右信息，点击“使用此热键”才提交给待测试配置；取消不改变待测试热键。首次完整向导第 5 步选择热键，重新集成则直接从选择热键开始，说明与测试均沿用所选热键。更换热键会使旧绑定重新进入待验证状态，必须重新完成真实语音转文字验证。关闭点按模式后选择只支持点按的工具时，必须明确确认开启点按模式，不会自动改变用户的选择。

组合键在语音开始时依次按下修饰键和主键，音频尾部发送完毕后先释放主键，再反向释放本次持有的修饰键；保留用户正在按住的实体修饰键。语音组合键与单独语音键均从 HID 入口通过公开 CGEvent 接口发送，使输入工具的较早事件监听也能收到组合键；事件保留独立来源，最终修饰键标志由组合键会话完整提供，发送时不再重新继承系统快照。HID 快照可能含有本次注入的修饰键，组合键释放时会排除本次持有的全部修饰键，避免已经松开的键被后续释放事件重新带回；单独 Command／Option 也沿用 Fn 的自身状态排除规则，并保留另一侧实体修饰键。更换触发键不会改变音频接收、尾部排空与结束流程。使用组合键需要辅助功能权限，目标工具必须支持该组合的按住说话模式。点按转换使用同一套既有收音、等待焦点、音频暂存与尾部排空流程，点按当前选择的热键或组合键。macOS 听写的专用双击启动仍限定 Fn；不兼容的选择会阻止向导继续，不会自动改回 Fn。

完成页按本次流程显示实际配置摘要：首次设置包含遥控器、按键检测、麦克风、热键、点按模式、输入工具与语音验证；添加遥控器只总结设备和按键检测；重新集成只总结热键、模式、工具与语音验证。验证标记必须匹配正式保存的工具、热键及模式。最后一步只提供“打开遥控搭子”主操作：首次完整设置进入通用页，添加遥控器进入遥控器连接页，重新集成进入输入法集成页。跳转目标仅在当前运行期间保留，重新启动应用仍默认进入通用页。

按键映射的“自定义快捷键”通过“选择快捷键…”打开与语音热键共用的 MacBook 键盘弹窗，支持点击按键或实体键盘录入。普通映射允许单个按键；语音热键保留专用校验。只有点击“使用此热键”才保存，取消或关闭弹窗保留原配置。页面不再嵌入另一套快捷键选择器。

新设备按自身型号初始化默认按键映射，不复制当前选中或其他设备的配置。单台设备的修改和恢复默认仅作用于本设备；设备间切换与重启保留各自配置，未选设备时的全局配置不覆盖新设备。

G9N9N 通过标准蓝牙电量服务提供有效读数时，设备卡片显示电量百分比，包括 0%；没有读数时不显示百分比。
